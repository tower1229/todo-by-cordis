## 01 产品定义与目标

### 1.1 一句话定义

“哆啦AI梦”是一个移动端优先、响应式的 Web Todo 应用。用户通过自然语言提出软件改造需求，AI 发现当前扩展契约，生成或修改插件，经验证后在运行中发布；应用还能依据故障记录尝试修复插件，并保留版本与回归经验。

初始状态是一个可正常使用的基础 Todo，而不是空白工具箱。基础待办、界面、存储、任务流程和 AI 改造流程均以插件组合存在。用户新增的插件列表初始为空，系统插件可查看但默认折叠。

### 1.2 核心产品命题

**同一个应用、同一批任务数据，在持续使用中获得新字段、新行为、新界面和新流程。** 演示重点不是安装预制功能，也不是每次重新生成网站，而是运行中的应用接受受控、可验证、可保留的改造。

| 概念 | 在本产品中的含义 | 不应混淆为 |
| --- | --- | --- |
| 使用软件 | 新建、查询、编辑、完成任务 | 每次操作都生成代码 |
| AI 业务功能 | 已安装估时插件调用模型分析任务 | 软件因此自动完成了一次迭代 |
| 软件自迭代 | AI 生成或修改插件、验证、发布并保留改进 | 只改变一段对话回复或临时页面 |
| 自修复 | 系统从故障触发诊断，修复实现并通过回归 | 重试网络请求或吞掉异常 |
| 流程演化 | 任务生命周期或改造流程的实现被替换 | 将核心实现固定后仅追加外围钩子 |

### 1.3 目标用户与使用情境

主要用户是希望根据个人习惯改造待办应用的人，以及需要向观众演示 AI 软件迭代能力的开发者。首期按“一个部署实例、一个所有者、一个工作区”设计，不引入组织与协作系统。

用户在手机上完成日常记录、提出改造、预览和批准；在平板或电脑上获得更多并排空间和诊断信息。核心能力不得因移动端屏幕较小而缺失。

### 1.4 成功条件

一次完整演示至少证明：生成一个原本不存在的业务插件；在同一插件上完成一次版本迭代；再生成一个使用前者能力的插件；替换一次兼容的业务流程实现；完成一次真实生成修复代码的故障闭环。新版本在刷新页面和重启服务后仍然存在。

“支持任意需求”“每次修改必成功”“模型持续自主变聪明”不是产品承诺。失败必须能停止、说明原因并保留可恢复的版本。

## 02 已定方向、默认决策与范围

### 2.1 已确定的产品要求

| 编号 | 已确定要求 | 产品含义 |
| --- | --- | --- |
| U-01 | 以 Todo List 作为固定业务领域 | 不再生成任意类别的独立工具 |
| U-02 | 通过对话修改外观、体验、数据与行为 | 不要求用户编程或理解扩展点名称 |
| U-03 | Todo 全业务链路提供扩展契约 | 覆盖输入、决策、数据、查询、展示、事件与调度入口 |
| U-04 | 功能以插件存在并能继续组合 | 插件既消费接口，也能提供新接口 |
| U-05 | 核心流程与核心循环也可以是插件 | 不能交付为“硬编码核心＋外围插件” |
| U-06 | 错误收集和 AI 自动尝试修复 | 采集由宿主机制强制提供，不依赖生成代码自觉实现 |
| U-07 | 响应式、移动端优先的 Web 应用 | 手机端完成日常操作和整个改造闭环 |

### 2.2 本版采用的建议默认值

首期采用自托管的单用户服务端作为数据和插件版本的权威存储；浏览器缓存用于草稿、最近数据和断网展示，不承诺完整离线写入。这样手机访问同一实例时不需要在移动浏览器内构建代码。未提供任何账户凭据或模型配置时，应用仍应允许基础待办使用。

服务默认只面向本机；需要手机连接时，由维护者显式开放可信网络入口并启用实例访问认证。公网匿名执行生成代码不属于首期交付。简体中文为首发语言，时间按工作区设置的 IANA 时区显示，默认由浏览器初次检测后让用户确认。

产品名沿用“哆啦AI梦”；视觉使用原创抽象助手图标与中性应用界面，不把任何特定角色素材作为交付依赖。

### 2.3 优先级定义

P0 是首期可交付演示必须具备的能力；P1 是后续增强，不构成首期验收门槛；P2 是探索方向。架构可扩展不等于首期必须实现所有扩展的业务功能。

| 范围 | P0 必须交付 | 后续或不做 |
| --- | --- | --- |
| 基础应用 | 任务增改、完成/重新打开、删除/撤销、搜索、状态筛选、持久化 | P1 批量操作、拖拽排序、富文本、附件 |
| 自然语言改造 | 需求识别、能力发现、增量修改、方案、验证、预览与发布 | 不做无边界整站生成、任意依赖安装 |
| 扩展机制 | 字段、服务、事件、界面、查询、命令、流程替换接口 | P1 外部系统适配器、复杂调度提供者 |
| 代码与配置 | 配置修改也有版本；至少一个非预制逻辑插件由 AI 生成 | 不以“切换预制模板”冒充生成 |
| 核心流程 | 默认流程以插件实现；证明一次兼容流程替换 | P1 任意历史状态迁移、长流程多版本并行 |
| 运行治理 | 持久化版本、候选隔离、发布门禁、失败恢复、依赖检查 | P1 插件市场、组织权限、签名分发生态 |
| 自修复 | 统一采集、可复现故障、有限尝试、独立验证、受控发布 | 不保证所有故障可自动修复 |
| 移动体验 | 手机端完整闭环、平板和桌面适配、基础无障碍 | P1 安装型 PWA、完整离线编辑、系统推送 |

### 2.4 首期范围控制

需求是否可实现由“当前契约＋可用服务＋允许依赖＋权限＋预算”决定，而不是由固定功能白名单决定。缺少新外部服务或需要破坏性迁移时，先说明限制并提出可执行的最小版本，不无限尝试。

## 03 信息架构与响应式布局

### 3.1 一级导航

手机端使用三个底部导航：“待办”“哆啦AI梦”“插件”。设置入口在页面顶部；迭代记录入口在 AI 页顶部，并可从插件版本和异常卡片进入。导航上的提示点表示待审批或失败，不用颜色单独表达状态。

| 页面/入口 | 核心内容 | 手机端 | 平板与桌面 |
| --- | --- | --- | --- |
| 待办首页 | 筛选、任务列表、新增、进行中改造提示 | 单列主页面 | 列表为主，可并排打开详情 |
| 任务详情 | 标题、描述、动态字段、允许操作、关联插件 | 独立全屏子页面 | 右侧详情区或抽屉 |
| 哆啦AI梦 | 对话、目标范围、方案、执行与预览卡片 | 独立全屏主页面 | 桌面可作为右侧常驻面板 |
| 插件中心 | 已安装、状态、依赖、搜索、系统插件 | 卡片列表 | 更密集列表，但功能不增加门槛 |
| 插件详情 | 配置、版本、权限、依赖、异常与操作 | 独立全屏子页面 | 内容页或侧栏 |
| 迭代详情 | 请求、方案、构建、测试、发布、回退证据 | 时间线与折叠详情 | 可并排对比版本 |
| 设置与恢复 | 模型连接、自动修复、音效、数据、维护入口 | 全屏页面 | 常规设置内容区 |

建议路由为 /tasks、/tasks/:id、/ai、/plugins、/plugins/:id、/changes/:id、/settings。页面刷新与浏览器后退必须恢复所处位置；URL 不携带令牌、任务正文或敏感日志。

### 3.2 响应式规则

| 视口宽度（CSS px） | 布局要求 | 主要交互 |
| --- | --- | --- |
| 320–767 | 单列、底部导航；任务详情与 AI 预览全屏 | 不并排压缩聊天与列表；复杂内容改纵向分组 |
| 768–1199 | 紧凑导航＋主体；空间足够时列表与详情双栏 | AI 可独立页或覆盖面板；不同时塞入三个工作区 |
| ≥1200 | 左导航约 208 px＋主内容＋可折叠 AI 区约 360–420 px | 主内容可用宽度不足 480 px 时自动收起 AI 并排模式 |

断点是本版布局决策，不是设备类型判断。横屏、窗口缩放与桌面高倍缩放都按实际可用宽度适配。任何插件必须响应自身容器宽度，而不是假设永远占满浏览器。

### 3.3 导航与上下文保留

切换一级导航保留搜索条件、列表滚动、未发送对话草稿和已选任务。关闭 AI 页面不等于取消服务端改造任务；重新进入后查询真实状态。任务详情点击“返回”恢复原列表位置。

手机端同一时刻最多一个主覆盖层。预览、权限确认和代码详情不连续叠加弹窗；需要深入时打开子页面并保留返回路径。键盘弹起时优先保住输入框和提交动作，底部导航可临时收起。

## 04 基础 Todo 与日常交互

### 4.1 默认应用组合

默认业务字段为标题、描述、任务状态及必要系统元数据，不预置优先级、估时等演示扩展。默认视图提供“未完成 / 全部 / 已完成”，初次进入显示未完成任务，按创建时间倒序，稳定并列顺序由 ID 兜底。

| 需求编号 | 交互与规则 | 验收结果 |
| --- | --- | --- |
| TD-01 | 首页右下或底部提供明确“新增任务”；空列表也有同一入口 | 不依赖聊天才能创建第一条任务 |
| TD-02 | 新增打开表单：标题必填，描述选填，插件字段按声明追加 | 基础任务在无模型配置时可保存 |
| TD-03 | 标题去除首尾空白，建议上限 200 字符；描述上限 5,000 字符；只校验不擅自改写内容 | 空白标题不能提交；错误贴近字段展示 |
| TD-04 | 连续点击提交复用同一操作 ID；提交中按钮防重复但可离开页面 | 网络重试不产生重复任务 |
| TD-05 | 点击任务正文进入详情，点击状态控件仅发起当前流程动作 | 两个点击区域不会误触相互行为 |
| TD-06 | 编辑采用显式“保存”；离开有修改表单时提供保存、放弃、继续编辑 | 不静默丢失未提交内容 |
| TD-07 | 完成发起语义命令，由流程返回成功、拒绝或补充输入 | UI 不直接把 completed 置为 true 绕过流程 |
| TD-08 | 默认完成提交成功后显示反馈并移动到已完成视图；保留“撤销”入口 | 动画或声音失败不改变已保存事实 |
| TD-09 | 删除先软删除，显示 8 秒撤销；回收站保留 30 天为建议默认值 | 撤销不依赖 AI；彻底清空需确认 |
| TD-10 | 搜索标题和描述；筛选按状态类别，而非写死所有状态名 | 新流程增加状态后任务不会消失 |
| TD-11 | 多个浏览器操作采用版本检查；冲突返回当前值并提供重新应用修改 | 旧对象不覆盖他处已保存的内容 |
| TD-12 | 详情内提供“用 AI 改造相关功能”，明确为功能改造，不是编辑本条任务 | 进入 AI 时显示范围标签和关联 taskId |

### 4.2 任务行与详情

任务行包含状态操作、标题、最多两行摘要式元信息、插件徽标和更多菜单。长标题允许换行；更多插件字段收纳为“另有 N 项”，点击进入详情，不无限拉高每行。颜色必须配文字或图标。

默认详情支持编辑、完成/重新打开、删除。新增字段按“基础信息 / 插件字段”分组，展示字段所属插件。流程返回补充输入时，打开相应表单；用户取消后任务保持原状态。

完成导致当前筛选不再包含该任务时，先完成状态确认，再移出列表；撤销成功后恢复在当前排序下的位置。快速连续点击相同状态操作合并或拒绝重复执行。

### 4.3 空、加载、保存失败与断网

首次空状态说明“先添加任务，或让哆啦AI梦改造这个应用”，给出少量示例请求，不自动执行。搜索无结果提供清空筛选；已有任务全完成使用普通完成态，避免遮挡操作的大动画。

首屏加载用有限骨架，重连展示最近数据和最后同步时间。断网可查看缓存及保留表单草稿，但 P0 不宣称草稿已保存，也不自动排队复杂写入。保存失败保留输入并可重试。服务端已成功但响应丢失时，按操作 ID 查询结果，不能重复创建。

## 05 对话驱动改造

### 5.1 对话入口与意图边界

| 需求编号 | 产品规则 |
| --- | --- |
| AI-01 | 全局入口默认范围为“整个应用”；插件详情入口固定显示插件名与当前版本；任务详情入口携带任务作为示例，不自动授权读取全部任务。 |
| AI-02 | 区分“操作任务”“配置功能”“修改/新增插件”“替换流程”“解释现状”。新增一条任务不创建插件；修改已有能力沿用 pluginId 并增加版本。 |
| AI-03 | “把它改成红色”等目标不明确请求，先展示候选目标或问一个必要问题，不猜测全局修改范围。 |
| AI-04 | AI 查询实时能力目录及已装插件，再决定复用、配置、修改或新增；不每次把整个项目和全部任务送入上下文。 |
| AI-05 | 用户可从能力建议发起请求，但不能被要求掌握 hook 名称、代码或依赖管理。 |

### 5.2 一次改造的用户旅程

对话提交后立即建立需求记录。AI 将请求转换为简短方案卡，说明“会改变什么、影响哪里、数据或权限变化、如何验证”。低风险清晰请求可直接进入候选构建；涉及新权限、流程变化或较大成本时先确认方案，确认后仍需执行真实验证。

方案确认不等于无条件批准任何最终代码。权限变化或最终范围偏离原方案时必须重新确认。所有授权绑定候选版本和产物摘要，不能在用户批准后暗换构建内容。

### 5.3 方案、执行与结果卡片

| 卡片 | 必备内容 | 用户操作 |
| --- | --- | --- |
| 需求方案 | 目标插件、改动摘要、依赖、数据影响、权限、验收案例 | 开始、调整需求、取消 |
| 执行状态 | 当前阶段、真实日志摘要、已用/剩余尝试预算、阻塞原因 | 停止、查看详情；不能伪造百分比进度 |
| 待审批候选 | 前后变化、测试数量与结果、预览、权限差异、可撤回性 | 应用、继续修改、放弃 |
| 发布结果 | 插件/组合版本、受影响功能、测试证据、发布时间 | 去体验、继续改、查看版本、撤回 |
| 失败结果 | 失败阶段、已尝试次数、保留的当前版本、可选下一步 | 修改需求后重试、查看诊断、结束 |

对话以用户可理解的状态解释为主，完整源码、差异和日志默认折叠。日志必须来自执行器；模型说“成功”不改变任务状态。

### 5.4 预览、修改与取消

预览使用脱敏样例或明确授权的数据副本，不写正式任务、不发送正式通知。手机打开全屏预览页，顶部标明“预览，尚未应用”，返回后仍是原候选卡。桌面可并排比较，手机采用“当前 / 候选”切换和逐项差异。

用户提出继续修改时，基于明确的候选或已发布版本，不遗失之前需求。首期每工作区只运行一个改造/修复写任务，其余进入可取消队列；相同插件发生新需求时可“补充到当前需求”或“停止后新建”，不能并行覆盖。

停止会取消可取消的工具调用并阻止发布；若已进入不可中断的提交段，则完成提交或恢复后显示最终状态，不假称即时取消。页面关闭后服务端可继续处理，但无人批准的高风险候选不得发布。

### 5.5 发布交互默认策略

R0 为仅允许范围内的外观配置，可在用户主动提出后自动应用并提供撤回。R1 为新增功能或业务代码，默认预览后确认；用户可显式开启“同权限范围低风险修复自动发布”。R2 为流程替换、权限扩大或数据语义变化，必须确认。治理组件和核心契约升级为维护者权限，不由普通对话直接发布。

## 06 插件化架构与扩展契约

### 6.1 架构约束

**AR-01：不允许把 Todo 的业务流程写成不可替换宿主核心。** 基础任务 UI、存储提供者、工作流驱动、LLM 适配器、字段注册、视图、改造 Agent 与验证/发布服务均按公共契约组装。最小启动器只负责建立运行环境、加载受信任组合及进入恢复模式。

**AR-02：接口与实现分离。** 其他插件面向任务服务、流程契约和能力注册表，不直接引用默认流程的内部实现。契约定义可独立版本化，但本轮生成插件不得擅自改变宿主基础契约。

Cordis 的服务、依赖注入、事件与受管理副作用可作为运行时机制参考 [S1]；dsh 的 Agent 接口与具体循环分离可作为流程可替换的参考 [S2]。这些参考不等于本应用已有实现，也不指定必须 fork 整个 dsh。

### 6.2 插件类别

系统插件提供默认 Todo 与治理服务；功能插件实现用户生成的扩展；流程插件决定任务命令或 AI 改造任务如何推进；组合定义记录本工作区启用了哪些精确版本。类别用于解释用途和权限，不创建无法互相组合的第二套插件机制。

一个插件可以同时提供字段、界面、事件处理和服务；一个用户需求也可以生成多个协同插件，并作为一个变更集统一验证和发布。

### 6.3 扩展点目录

| 接口族 | 契约要求 | 组合规则 |
| --- | --- | --- |
| EX-01 命令与输入 | 声明命令、输入输出 Schema、作用域、取消语义 | 输入转换有确定次序，命令名不得无声覆盖 |
| EX-02 提交前处理 | 校验、补充、拒绝及需要用户输入的结构化结果 | 串行、可终止、有限时；不能执行无记录外部副作用 |
| EX-03 字段 | 稳定 key、类型、默认值、校验、控件与隐私等级 | 命名空间唯一；类型兼容规则明确 |
| EX-04 提交后事件 | 事实事件、前后版本、变更字段与来源 | 观察者可并行；失败不反向撤销已提交事实 |
| EX-05 查询与视图 | 筛选、排序、分组、聚合与结果 Schema | 多筛选按交集；主排序单选；顺序显式 |
| EX-06 UI 插槽 | 声明位置、数据、允许动作、容器约束与替代态 | 受控顺序、多实例限制、独立失败降级 |
| EX-07 服务 | 接口版本、方法、Schema、权限及依赖 | 单提供者或显式注册表；不能靠加载顺序抢占 |
| EX-08 流程驱动 | 命令入口、状态定义、允许动作、恢复和停止契约 | 同一活动流程绑定唯一有效提供者 |
| EX-09 调度入口 | 时间、时区、取消、幂等与错过执行策略 | P0 提供前台/在线基础能力；可靠后台提醒为 P1 |
| EX-10 诊断与指标 | 统一故障、运行上下文、版本与日志关联 | 核心采集自动注入，插件可追加语义 |
| EX-11 生命周期 | 激活、停止、清理、状态恢复、依赖就绪 | 可取消工作要登记；卸载等到清理边界 |

扩展点覆盖业务边界，不暴露每个内部函数、DOM 层级或数据库实现细节。新增能力可以由插件注册新服务或事件，但需符合基础协议且可被能力目录检索。

### 6.4 能力发现与插件契约

AR-03：运行时目录必须准确区分“已声明”“已安装”“已激活”“缺失依赖”和“无权调用”。目录包括真实输入输出、版本、示例、派发语义、错误语义、耗时/成本类别、支持的 UI 容器及权限。

AR-04：依赖用接口及版本范围表达，发布时解析成精确版本锁定。检测循环依赖、缺失服务和接口不兼容，不让插件永久静默等待。构建候选时保存目录快照与组合版本；发布前重新检查。

AR-05：禁止生成插件直接更改其他插件私有状态或 DOM。样式只通过主题令牌与局部容器；业务读写只通过授权服务。技术可替换不代表所有用户都能修改所有插件。

## 07 数据模型与字段演化

### 7.1 领域对象

以下是逻辑数据要求，不是强制数据库表设计。

| 对象 | 必需信息 | 约束 |
| --- | --- | --- |
| Task | id、title、description、state、workflowId、workflowVersion、extensions、revision、创建/修改/删除时间 | id 稳定；所有写入检查版本；状态不能只用布尔值表达 |
| WorkflowDefinition | 状态集合、状态类别、动作定义、输入要求、兼容性 | 默认 open/done；UI 按声明展示动作 |
| FieldDefinition | namespace.key、类型、单位、默认值、校验、展示、所有者 | 稳定标识；禁止随意改名导致数据丢失 |
| PluginVersion | pluginId、不可变 versionId、源码、构建产物、摘要、契约与测试 | 同一版本不可被静默覆盖 |
| CompositionRevision | 精确插件版本、配置、能力授权、依赖锁、兼容标记 | 一次发布和撤回的整体参照 |
| ChangeRequest | 用户需求、目标、基线、方案、预算、状态、产物引用 | 对话与发布一一可追溯 |
| Incident | 归属版本、故障指纹、最小复现、脱敏上下文与处理状态 | 同一故障聚合，未知归属不乱改代码 |
| RegressionCase | 固定输入、预期行为、来源、适用契约与版本 | 修复不能删除或弱化已有基线 |

### 7.2 状态和默认行为

Task.state 为可扩展字符串，流程定义把具体状态映射到 open、active、review、done 等状态类别。默认流程只使用 open 与 done。“已完成”筛选基于类别；完成时间只在实际进入 done 时记录。Task.workflowVersion 表示当前任务采用的状态语义版本，工作流升级必须提供兼容说明。

状态控件执行“请求推进/请求完成”命令，不能由 UI 直接写状态。拒绝、等待补充信息和成功都使用结构化结果。动画和统计只响应提交成功的事实事件。

### 7.3 新增字段

DATA-01：P0 支持短文本、长文本、数字、布尔、单选、多选和日期时间字段。日期时间记录值及解释所用时区；数字可带单位，不依赖显示文本猜测含义。

DATA-02：新增字段必须可选或具备明确默认值。旧任务缺值采用逻辑默认或分批补齐，不允许整批重写时覆盖其他用户修改。字段写入只更新授权路径，不提交完整旧对象。

DATA-03：保留来源、人工覆盖标记和必要的输入版本。停用/卸载功能默认隐藏 UI 并保留字段值；用户可显式导出或清除某插件数据，清除前确认并说明依赖影响。

DATA-04：P0 不自动执行删字段、改变字段类型或任意破坏性迁移。需要此类变化时停止自动发布，提供迁移说明；不能通过换新字段名偷偷丢弃原数据。

### 7.4 持久化与恢复

正式任务、插件源码/产物、配置、组合版本、回归案例和改造记录均持久化。浏览器刷新和服务进程重启不得清空已发布插件。源码导出不包含密钥；恢复包导入先校验格式与权限，默认不执行未经确认的插件。

插件回退只回退实现与兼容配置，不回滚整个数据库到旧快照。发布期间新增的任务和用户手动字段修改必须保留。备份用于受控恢复，不作为每次撤回都覆盖全部业务数据的捷径。

## 08 业务扩展与核心流程演化

### 8.1 场景 A：创建后 LLM 估时

EXT-A 的用户需求为“创建任务后自动估时，并显示在任务旁”。插件同时注册 estimateMinutes、估时状态、人工覆盖信息、任务行徽标、编辑入口与估时服务。任务先保存，再发布 task.created；估时订阅者异步执行，不阻塞创建。

估时状态至少有未估时、排队、分析中、完成、失败、已手动设置。结果必须为约定范围内的分钟数或明确未知，不以任意模型文本写入数字字段。模型解释是建议，不宣称真实耗时。

输入使用任务 ID、标题/描述快照、相关字段版本和插件版本。返回时任务若已删除、输入已变或人工估时已设置，旧结果不得覆盖；可显示“任务已修改，重新估时”。插件只在相关输入变更时重新触发，不因自己的估时写入递归调用。去重键至少覆盖任务、输入版本与分析规则版本。

首次启用说明会把哪些字段发送给模型，授权后作用于新任务；“估算已有任务”是单独的批量动作，先说明数量和预算。断网、限流、取消按对应状态处理，不默认生成代码修复。用户手动值优先，除非显式选择“用 AI 重新覆盖”。

### 8.2 场景 B：基于已有能力继续扩展

EXT-B 的用户需求为“增加 20 分钟以内任务筛选”。AI 发现估时字段和查询契约后生成新的筛选插件；缺失估时的任务默认不纳入结果，并在筛选说明中写明。不再实现第二套估时逻辑。

卸载估时插件时展示依赖筛选插件清单；可以取消，或者确认同时停用依赖方并保留所有数据。需要调用活跃估时服务与仅读取保留字段属于不同依赖类别，应准确区分。

### 8.3 场景 C：替换任务核心流程

EXT-C 的用户需求为“完成任务前必须写一句复盘”。AI 修改或新增工作流实现，沿用任务公共接口，增加 review 状态或补充输入决策，以及复盘字段/表单。默认工作流不被 UI 私有逻辑绕过。

P0 的验收实例必须完成一次真实的兼容替换：旧 open/done 任务保持原语义；新完成请求先进入 review 或等待复盘，提交后才进入 done；取消复盘不算完成。已有完成记录、任务 ID 和字段值不被清空。

替换前校验新旧状态映射、可用动作、存储兼容、恢复路径和受影响任务数量。首期采用短暂停止新写入、排空当前命令、提交兼容组合、恢复入口的方式，不承诺任意指令中间无缝替换。

撤回含 review 状态的流程必须显式显示映射策略，例如 review 转回 open、复盘字段保留，并获得确认；若无法安全映射，则保留旧流程或只读恢复，禁止强行回退。P0 演示需验证一次具有明确映射的撤回路径。

### 8.4 AI 改造流程本身的插件化

AI 改造 Agent 通过独立驱动契约提供“理解、生成、修复”等步骤，验证与发布是其调用的独立服务。接口允许后续更换驱动，而不重写 UI、需求记录和版本库。

首期要求通过配置替换一个兼容驱动，并跑通契约烟测；不要求公开演示 Agent 现场改写自己的治理权限。已运行的改造任务在安全边界结束或停止后再换驱动，不能同一任务前半段和后半段偷偷使用不同规则。

## 09 插件中心与管理交互

### 9.1 列表和详情

PM-01：插件列表区分“我的扩展”与默认折叠的“系统组件”。卡片显示名称、用途、当前版本、启用状态、健康状态和是否被依赖。没有用户插件时展示从对话创建入口，不伪造安装量或推荐市场。

PM-02：详情包含概览、配置、版本、依赖/权限、问题记录。主要动作是配置、让 AI 修改、停用/启用和撤回；卸载位于更多菜单。系统组件标记“默认应用组成”，无兼容替代者时不允许直接停用关键提供者。

| 动作 | 产品规则 | 界面反馈 |
| --- | --- | --- |
| 启用 | 校验依赖、版本、权限和冲突，再激活 | 等待依赖、启动中、已启用或明确错误 |
| 停用 | 检查依赖、停止工作、撤销注册，默认保留数据 | 说明会消失的功能和受影响插件 |
| 配置 | 按 Schema 渲染；保存后创建配置修订 | 无效值原地提示，不破坏当前有效配置 |
| 继续修改 | 将稳定 pluginId、当前版本和选中范围带入 AI | 不创建同名重复插件 |
| 撤回 | 预检兼容与依赖；退回上一个可用组合 | 说明实现变化及数据保留方式 |
| 卸载 | 停用后移出活动组合，保留历史产物以便恢复 | 单独询问是否清理数据，默认不清理 |

### 9.2 插件状态

运行状态与版本状态分开表达。运行状态包括未启用、缺依赖、启动中、运行中、降级、隔离、停止中、启动失败；版本状态包括草稿、验证中、待批准、已发布、已替代、已撤回。不得用一个“失败”混淆构建失败与线上故障。

### 9.3 插件 UI 约束

声明支持的插槽、最小宽度、折叠策略和空/错误状态。新菜单项不能覆盖全局新增任务、返回、停止改造、撤回与恢复入口。插件停用时列表保持焦点和滚动；正在编辑其字段时先保存草稿或明确提示。

## 10 生成、验证、发布与热更新

### 10.1 变更状态机

CH-01：一条变更依次经历已接收、待澄清/待授权（可选）、计划完成、生成中、构建中、验证中、待批准、发布中、已生效；任一阶段可转为已取消、失败或被新请求替代。发布失败有单独的恢复中、已恢复和需人工处理状态。

状态由执行器持久化推进；服务重启后查询产物与发布事务的真实状态。无法安全继续的步骤标为已中断并等待处理，不因浏览器重新连接就重复执行。

### 10.2 候选生成要求

CH-02：每次生成固定基线组合与目标 pluginId。AI 优先做配置变更或最小代码修改；允许使用 SDK、统一 UI 组件和受信任依赖。不得每个请求都重新搭脚手架、重装任意包、修改未授权组件。 dsh 的动态工具提供了检查与版本管理参考，但其进程内定义与语法检查不替代这里的持久化发布和业务验证 [S3]。

CH-03：候选产物包括源码、构建产物、元数据、依赖锁、权限清单、接口变化、测试、新增字段/状态影响和回退说明。纯配置修改也纳入版本，不强迫为换主题生成代码。

### 10.3 验证门禁

| 门禁 | 必须验证 | 失败行为 |
| --- | --- | --- |
| 构建与静态检查 | 语法、类型、允许依赖、入口、产物完整性 | 不进入运行预览 |
| 契约与权限 | 注入依赖、接口兼容、字段所有权、API 访问范围 | 拒绝不兼容或越权候选 |
| 功能验收 | 需求中的可观察输入输出和交互 | 不能用无异常代替正确结果 |
| 基础回归 | 新增、编辑、完成、删除、保存与默认列表 | 任何必测失败不得发布 |
| 插件集成 | 受影响依赖方、字段共存、事件顺序与去重 | 作为组合检查，非只测单插件 |
| 移动端与无障碍 | 320/390 宽布局、触控、标签、关键表单、减少动态效果 | 不因桌面通过而跳过 |
| 生命周期 | 卸载、重载、取消、清理、重复更新、数据保留 | 不留重复监听、工作或孤立服务 |
| 修复专属 | 原失败案例在旧版失败、新版通过；既有测试不变差 | 未复现不得宣称根因已修复 |

验证器不接受修复 Agent 删除保护性测试、弱化期望或屏蔽采集作为修复。需求确实变化时走独立方案确认，不伪装为错误修复。LLM 功能测试用可控桩验证协议和状态，另做明确标注的真实模型烟测；不能拿桩响应冒充现场模型成功。

### 10.4 发布与切换

CH-04：发布锁定工作区写变更，检查当前组合仍等于候选基线。不一致则重新验证或重新生成，不覆盖他人更新。审批关联准确产物摘要、权限和组合版本。

CH-05：候选预先加载到非正式环境完成检查；按生命周期安全边界停旧启新。跨多个插件的变更集对用户呈现为一个版本，任一必要插件失败即恢复原组合。前后端能力先校验协议并准备，再切换活动指针；不能先显示新版界面却仍调用不兼容旧后端。

CH-06：字段草稿、任务 ID、已保存内容、列表筛选和滚动尽量保留；允许相关插件重新挂载。用户编辑中的目标控件暂缓替换，待保存或放弃后继续。首期热更新定义为“不整页刷新、不丢任务、不破坏无关功能”，不承诺任意内存状态迁移。

CH-07：如旧插件无法在规定清理时限内停止，停止发布并隔离候选；不得让两个独占提供者同时写入。多页面连接的旧客户端检测组合版本不符后停止旧协议写入，保留草稿并重新握手。

### 10.5 成功与回退

发布完成要求服务端激活、当前操作客户端确认和关键烟测通过；仅构建成功或组件加载成功不算用户已获得功能。P0 单工作区部署不承诺所有离线页面同步在线确认。

候选发布后关键烟测失败时自动恢复兼容旧组合。后续任意故障不直接认定是新版导致，先做归属与影响分析。回退无安全状态映射时进入恢复界面，不擅自删除新数据。

## 11 错误收集与自修复

### 11.1 采集覆盖与归属

ERR-01：宿主自动覆盖构建、加载、UI 渲染、用户动作、异步回调、服务调用、工作超时、资源释放和提交失败。React Error Boundary 只作为渲染层机制，不能代替动作与异步捕获 [S9]。

ERR-02：每次插件执行绑定 pluginId、versionId、compositionRevision、taskId（必要时）、operationId、traceId 和来源；错误带精确产物摘要与源码映射。整页/进程失去响应需要运行器或外部监控报告，不能假设失控代码还能自行上报。

ERR-03：故障包包括错误类型、堆栈、最小输入、相关版本、调用路径、必要状态和期望行为。默认不收集全量任务、密钥和剪贴板。不能归属时标记未知，先请求确认或观察，不对随机插件发起修复。

### 11.2 分类与自动动作

| 故障分类 | 默认动作 | 是否自动改代码 |
| --- | --- | --- |
| 用户输入不符合明确规则 | 展示校验说明 | 否 |
| 用户取消、权限拒绝 | 正常停止或请求授权 | 否 |
| 网络断开、超时、限流 | 有限重试与退避，保留业务状态 | 否；重复后提示配置/环境检查 |
| 插件渲染/逻辑异常 | 降级对应功能、创建故障、尝试复现 | 可在已授权范围内 |
| 测试发现错误结果 | 保存独立期望与最小失败样例 | 可 |
| 数据完整性或越权异常 | 立即阻止危险行为、冻结相关写入 | 不自动发布修复，需确认 |
| 验证器/发布器/采集器故障 | 进入维护恢复通道 | 不由普通修复任务修改治理链 |

### 11.3 自动修复闭环

ERR-04：发现、分类、聚合、定位、隔离影响、复现、生成候选、回归、按风险批准、发布、观察结果。至少记录“已复现 / 未复现 / 已缓解 / 已验证修复 / 未解决”，不将“错误暂未再次出现”自动写成修复成功。

ERR-05：默认开启本地采集。首次启用 AI 自动修复时说明上传的数据类型和预算；用户授权后可自动诊断及生成候选。业务代码修复默认待批准，开启低风险自动发布后才可在权限不变、独立测试全部通过时自动应用。流程与权限变化仍须确认。

ERR-06：同一插件版本＋故障指纹在建议 5 分钟窗口内聚合；同一故障最多 3 次候选尝试，跨自动重试持续计数，不通过换 incidentId 重置。修复失败、成本达限或重复出现时熔断，停止相关自动化，用户可修改需求后显式重试。

ERR-07：失败的修复候选不进入生产，不触发新的生产自修复风暴。人工改造和自动修复共享工作区队列；人工请求优先，已执行的修复在安全边界暂停。相同代码基线被替换时旧修复失效并重新评估。

### 11.4 故障时的用户体验

非关键动画或徽标失效，只降级对应区域；任务仍可操作，展示可关闭提示和“查看问题”。阻塞写入的流程故障使用明确错误页或只读态，不假装完成成功。修复中不锁整个应用，也不强迫用户停留聊天页。

恢复入口位于受保护启动路径，可禁用用户插件、加载最后可用组合和导出任务。普通插件即使改变主题、路由或主界面，也不得隐藏该入口。

## 12 界面状态、反馈与关键文案

### 12.1 全局状态表

| 状态 | 应显示什么 | 允许操作 |
| --- | --- | --- |
| 尚未配置模型 | “待办可正常使用；连接模型后可改造应用。” | 使用待办、进入设置 |
| 任务列表首次加载 | 少量骨架，不显示伪任务 | 导航和设置可用 |
| 离线缓存 | “当前离线，显示上次同步内容。”及时间 | 查看、保留草稿；写入不假报成功 |
| 改造排队 | 队列位置与当前占用任务 | 取消队列项、继续使用应用 |
| 需求超出能力 | 缺失服务/权限/契约的具体说明 | 采用简化方案或结束 |
| 生成/验证中 | 真实阶段、日志摘要与取消入口 | 切页不丢任务 |
| 候选可预览 | “尚未应用”，测试与权限摘要 | 预览、批准、继续修改、丢弃 |
| 新权限待授权 | 将发送/修改的数据和目的 | 同意或拒绝，拒绝不破坏现有功能 |

| 已生效但插件故障 | 具体失效功能及当前降级方式 | 继续使用其余功能、处理问题 |
| 修复达到上限 | “已停止自动尝试，当前版本未被替换。” | 手动处理、明确重试 |
| 依赖缺失/冲突 | 缺失项与可采取动作 | 启用依赖、取消当前操作 |
| 只读恢复 | 原因、最后可用组合及数据状态 | 导出、恢复、进入维护设置 |

### 12.2 通知规则

成功反馈用轻量提示，不遮挡任务；需用户决定的事项使用持久卡片并集中到待处理入口。Toast 不是保存失败、权限请求或关键故障的唯一载体。自动修复活动提供简短汇总，不每条日志都弹通知。

发声和庆祝效果只在事件真正成功后触发；批量或重放事件默认不连续播音。系统静音与减少动态效果优先于插件偏好。

### 12.3 文案原则

区分“方案已生成”“验证通过”“已应用”“已恢复”；避免笼统“完成”。LLM 估时注明为 AI 建议；修复未复现就显示未复现。任何失败都说明当前数据与版本是否安全，以及仍能做什么。

## 13 移动端、视觉与无障碍规范

### 13.1 移动端优先交互

UX-01：主要触控目标采用至少 44×44 CSS px 的产品设计目标，相邻危险动作保持清晰间距；44 不是对 WCAG AA 最小值的误述，WCAG 2.2 对相关目标规定的是 24×24 且存在例外 [S5]。

UX-02：正文和输入建议 16 px，辅助文字不低于 12 px；标题、正文、状态和辅助信息层级清晰。长任务、插件名、字段标签与错误内容能够换行，不使用全屏横向滚动补救排版。

UX-03：底部导航、输入栏和操作栏考虑设备安全区。软键盘弹起后输入与提交按钮保持可见，使用可用视口高度，不把固定高度表单藏到键盘后。表单内容长时可滚动，标题和关闭/返回可达。

UX-04：新增单行标题在非输入法组合状态下可用 Enter 提交；多行描述的 Enter 换行。AI 对话手机端 Enter 默认换行，显式发送按钮提交；桌面可配置 Enter 发送、Shift+Enter 换行。中文输入法选词不得触发提交。

UX-05：侧滑、长按和拖拽只能作为加速路径，必须有显式按钮等价操作。浏览器后退优先返回上一层，并处理未保存草稿。旋转设备不重置任务、方案或预览状态。

### 13.2 视觉系统及生成 UI

使用统一设计令牌管理颜色、字体、间距、圆角、阴影和动效。默认主题支持浅色、深色及跟随系统；用户通过对话调整时生成新的主题配置版本，不直接向全局任意注入 CSS。

生成 UI 优先使用宿主组件与声明式布局；需要自定义组件时仍受局部容器、权限及验证限制。任务徽标、表单字段、统计面板和错误态必须在 320 px 宽度下可用，无法并排则纵向布局。默认最多展示有限徽标，其余折叠进入详情。

### 13.3 无障碍要求

UX-06：以 WCAG 2.2 AA 相关要求为验收目标，而不是声称获得认证。普通文字对比度至少 4.5:1，大号文字按适用标准至少 3:1；主要交互和状态不能仅凭颜色区分 [S6]。

UX-07：非必要二维内容在相当于 320 CSS px 宽度下重排且不丢功能；代码差异与确有需要的表格允许局部滚动，不带动全页横移 [S4]。200% 文字放大后仍可操作，桌面 400% 缩放按重排检查。

UX-08：所有图标按钮有可读名称；表单标签和错误关联；任务状态变化与异步结果适度使用辅助技术通知。键盘可操作新增、完成、详情、预览、批准和撤回，焦点不得被固定区域遮挡。

UX-09：模态打开时管理初始焦点，Tab 留在模态内，Escape 按规则关闭；关闭后将焦点返回触发位置或合理替代位置。危险确认默认聚焦非破坏动作 [S7]。

UX-10：尊重 prefers-reduced-motion，提供减少动画和全局静音；不允许插件强行覆盖。音频可能受自动播放策略限制，拒绝播放时退化为可见反馈并提供手动启用，不重复制造报错风暴 [S8][S10]。

## 14 权限、安全与数据隐私

### 14.1 权限模型

SEC-01：所有插件申请最小能力，例如读取某任务、写自己的字段、监听特定事件、调用受控 LLM、注册特定 UI。字段所有权与任务写权限由运行器服务端校验，不只信任插件的自述。

SEC-02：模型凭据只保存在服务端受保护配置，不下发浏览器和生成插件。生成插件通过代理调用模型；默认不允许任意网络、文件系统、子进程、环境变量或依赖安装。外部请求和新权限需明确授权。

SEC-03：普通功能插件、流程插件和治理插件有不同发布权限。验证器、发布器、权限控制、恢复入口也可模块化/插件化，但普通 AI 改造不得修改它们、其基线测试或自身授权。

### 14.2 运行隔离

生成代码必须在明确约束的执行环境中运行。前端优先使用受控组件描述；自定义可执行 UI 需要受限制的独立环境和窄通信接口。逻辑执行必须具备终止超时工作的能力，服务调用强制鉴权与配额。

Cordis 负责生命周期与依赖组合，不作为恶意代码安全边界。Node 官方也明确 node:vm 不是安全机制 [S11]。P0 可把受信任 SDK 与有限依赖作为范围边界，但不能因“代码是 AI 写的”就视为可信。

具体隔离方案由研发设计评审决定并验证跨边界限制；若隔离目标未通过，不允许启用自由代码执行路径，应缩小到受限表达式/组件协议，而不是把风险藏在默认配置里。

### 14.3 数据发送与注入防护

SEC-04：为编码发送契约、源码和最少示例，不默认发送全部任务；为估时仅发送授权字段；为修复发送脱敏故障包。用户可查看某次调用包含哪些数据类别，拒绝后基础 Todo 仍可用。

SEC-05：任务标题、描述、插件文档及错误日志均视为不可信输入，不得被当作系统指令。内容中出现“删除数据库”“关闭审计”等文字不能扩大权限或改变审批规则。

SEC-06：实例访问认证、写操作鉴权、请求来源检查、敏感操作确认与基本频率限制为 P0。单用户不等于无需保护；未经认证的远程访客不能调用生成、运行、模型或发布接口。

### 14.4 留存、导出与清除

建议错误原始上下文保留 7 天、脱敏事件摘要 30 天；已批准回归案例作为测试保留，必须先去除敏感内容。用户可关闭正文采集并清空故障上下文，不影响已安装插件。

任务导出包含系统字段、插件字段定义与值；插件导出包含版本和测试但排除密钥；组合导出包括精确版本与权限声明。导入默认进入待确认态，不静默执行代码。清空工作区先提示并允许备份，不能通过一句含糊对话直接销毁所有数据。

## 15 非功能目标、预算与可观测性

### 15.1 性能与可靠性目标

以下为建议验收目标，测试时记录设备、浏览器、网络、服务端配置和模型，不能用目标数字冒充实测。

| 指标 | P0 建议目标 | 测量边界 |
| --- | --- | --- |
| 本地交互反馈 | P95 ≤100 ms | 点击到按钮/状态的即时反馈，不等于远程保存完成 |
| 基础任务保存 | P95 ≤500 ms | 同网段、单用户、1,000 条任务，无 LLM 阻塞 |
| 首屏可用 | P75 ≤3 s | 约定中档手机、4G 仿真、冷启动测试条件 |
| 任务检索/筛选 | P95 ≤200 ms | 1,000 条任务，10 个已装扩展的测试集 |
| 热切换中断 | 兼容短流程写入暂停目标 ≤2 s | 不含候选生成、构建和验证；超限保持旧版或提示等待 |
| 清理检查 | 连续 20 次启停/升级后，无重复处理和持续累积的登记资源 | 结合资源计数和操作次数，不声称内存零波动 |
| 数据保持 | 所有验收用例中无已确认写入丢失 | 含刷新、重连、崩溃恢复和撤回 |

### 15.2 生成和修复预算

BUD-01：一次需求默认最多 3 次候选尝试；每工作区最多一个写变更任务；每次模型调用建议 120 秒超时，整个变更建议 10 分钟硬上限；这些是可配置的执行上限，不是交付时间承诺。达到上限保留产物，停止并展示已用预算。

BUD-02：按模型真实使用量记录 token、调用次数及可计算费用；提供用户可设置的变更预算与日限额。无法取得可靠单价时只展示 token/调用量，不能伪造货币费用。高风险工具或追加权限不因预算剩余而自动授权。

BUD-03：LLM 估时使用独立业务调用预算，默认并发 2、网络类重试最多 2 次且带退避；不把调用重试计成新软件版本。超过预算转人工可处理状态。

### 15.3 事件与产品指标

需要记录 task.operation_requested/committed/failed、change.requested/planned/tested/approved/published/failed、plugin.enabled/disabled/rolled_back、incident.detected/reproduced/resolved/escalated 等结构化事件，均关联 operationId、版本和来源，默认不含正文。

核心指标包括：需求进入可验证候选的比例、用户批准率、发布成功率、撤回率、首次真实故障复现率、验证修复率、修复后复发率、单次变更成本，以及移动端各阶段放弃率。每个比率必须记录分子分母；用户取消、环境故障和代码失败分别统计。

演示报告必须区分真实模型执行、受控桩测试与已知缺陷注入。产品内的状态记录应能复核“哪段代码、哪些测试、何时发布”。

每条用例按 Given / When / Then 编写自动化或人工步骤；下表定义核心结果。P0 全部通过后才能宣称本版演示闭环完成。

| AC-21 | 新流程要求完成前复盘 | 当前 UI 按契约执行，新状态可见；取消不算完成 |
| AC-22 | 兼容流程替换时有旧任务 | 旧 open/done 任务与记录保留，无越权状态写入 |
| AC-23 | 撤回含 review 状态的流程 | 展示并确认映射，保留复盘字段，不丢任务 |
| AC-24 | 替换 AI 改造驱动 | UI 和记录系统无需修改；在安全边界完成切换 |
| AC-25 | 生成候选不能构建或测试失败 | 不发布，旧功能可用，展示真实失败阶段 |
| AC-26 | 变更集中一个必要插件激活失败 | 恢复原组合，不留下前后端半升级 |
| AC-27 | 插件完成动画抛异常 | 任务仍完成，仅效果降级并生成正确故障归属 |
| AC-28 | 固定缺陷样例触发错误结果 | 旧版复现失败，新版现场生成修复并通过基线 |
| AC-29 | 修复候选吞异常并返回空结果 | 功能验收失败，不能标为已修复 |
| AC-30 | 同一故障连续出现或超过尝试上限 | 聚合、熔断，不能创建新 ID 无限重试 |
| AC-31 | 网络限流或用户拒绝权限 | 不误触发改代码，按环境/授权状态处理 |
| AC-32 | 刷新、断线重连、服务重启 | 已发布产物保留；中断任务不伪装完成或重复提交 |
| AC-33 | 手机退出 AI 页再回来 | 真实任务继续可查，列表与对话上下文保留 |
| AC-34 | 320/390/768/1280 宽页面与插件 UI | 无全页水平溢出；手机可预览、批准与撤回 |
| AC-35 | 手机键盘、横屏、长文本、中文输入法 | 输入/提交可达，选词不误发，旋转不清空草稿 |
| AC-36 | 键盘和屏幕阅读器操作关键路径 | 标签、焦点、模态与状态可理解且可完成 |
| AC-37 | 减少动态效果及静音开启 | 生成插件遵守；音频拒播不导致业务失败 |
| AC-38 | 插件请求密钥、任意网络或他插件私有写入 | 运行器拒绝并审计，不靠 UI 禁用代替安全控制 |
| AC-39 | 任务/日志内容含恶意指令 | 不改变系统权限、测试基线或发布规则 |
| AC-40 | 故障发生在主 UI 或业务流程 | 可进入受保护恢复入口并导出/恢复 |
| AC-41 | 同插件反复启停、更新 20 次 | 不重复通知、分析或写入，无残留活动注册 |
| AC-42 | 数据导出与恢复包导入 | 扩展字段可恢复；代码先验证授权，不静默执行 |

## 17 演示脚本与交付分期

### 17.1 演示前准备

使用独立演示工作区和非敏感任务；清楚展示初始组合、源码版本、已装插件为空的用户扩展区。预先验证模型连接、预算、发布权限、移动访问和恢复按钮。准备演示说明与可重置的测试数据，不准备隐藏修复补丁。

| --- | --- | --- |

### 17.3 交付里程碑（不绑定工期）

M1：移动端基础 Todo、持久化、状态/动作契约、系统插件组合与恢复入口可运行。M2：实时能力目录、字段/UI/事件/服务扩展和一个手写测试插件验证契约。M3：AI 候选生成、版本库、测试门禁、预览、发布和撤回闭环。M4：估时、组合筛选和核心流程替换由真实生成完成。M5：故障采集、自修复、重启恢复、移动端与安全验收。

手写测试插件仅用于验证机制；正式生成演示必须记录由 AI 新生成或改写的源码。不得把 M2 的固定样例直接包装成 M4 已完成。每个里程碑以验收产物结束，不以“页面基本完成”结束。

## 18 风险、决策与交付检查

### 18.1 主要风险

| 风险 | 对策 | 不接受的替代做法 |
| --- | --- | --- |
| 需求仍可能超出模型能力 | 契约发现、最小修改、有限依赖、预算与停止机制 | 宣称任意需求必然交付 |
| 为追求全扩展过度抽象 | 先实现业务边界契约，用三类生成场景验证 | 给所有内部函数加钩子当作产品能力 |
| 多插件组合相互影响 | 明确顺序/互斥、依赖锁、组合回归 | 只测单插件或靠安装顺序隐式决策 |
| 自修复修改自己的评判标准 | 独立门禁、固定回归、权限隔离 | AI 自述成功就发布 |
| 手机端被日志与对话挤满 | 独立入口、摘要卡、全屏预览、详细信息折叠 | 把桌面三栏缩小到手机 |
| 热更新破坏状态和用户输入 | 安全边界、版本检查、草稿保留、兼容回退 | 直接清空页面或还原整库快照 |
| 生成代码破坏宿主 | 受限执行、能力代理、终止机制和恢复通道 | 将 Cordis 或 node:vm 当作完整安全沙箱 |

### 18.2 研发设计评审需要产出的决策

本 PRD 已采用可推进默认值，不要求再次确认已决定的插件化与移动优先方向。研发开始前应记录：Cordis 采用的精确版本与来源；是否复用 dsh 作为改造执行器；受限 UI 与逻辑执行隔离方案；默认存储与发布事务方案；模型适配器与预算计量；移动访问部署与认证方案。

这些是技术实现决策，不得改变以下产品底线：业务核心可替换、插件可以继续提供扩展能力、手机端可完成闭环、错误可归属、独立验证、持久化版本、有限自动修复与可恢复状态。

### 18.3 交付物清单

交付包括：可运行 Web 应用与自托管说明、默认插件组合和契约目录、生成/发布/恢复操作说明、P0 验收报告、真实移动端检查记录、独立演示工作区与明示故障脚本、已发布源码/产物/测试/版本的可追溯记录。

本版不要求插件市场、多人协作或复杂外部集成作为交付前置，也不允许用取消核心流程插件化来简化已确定目标。

### 19.2 术语

插件：具有稳定身份、声明式契约和受管理生命周期的功能单元。插件版本：同一插件的不可变实现或配置修订。组合版本：工作区内所有启用版本、配置与授权的确定集合。扩展点：具有明确语义、输入输出和组合规则的公开边界。候选：通过部分或全部验证、尚未成为正式活动版本的产物。热更新：在安全边界替换实现，不要求整页重载，不承诺任意内存状态迁移。回归案例：用于防止同类缺陷再次出现的可执行检查。自修复：从真实故障到验证改进的闭环，不等于重试或隐藏错误。

**文档结论：Todo List 是首个默认组合，而不是不可改变的核心。产品价值是让同一个应用在明确契约与验证约束下持续扩展、组合、修改并保留改进。**
