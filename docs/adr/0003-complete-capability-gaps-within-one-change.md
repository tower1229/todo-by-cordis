# 自主发现并在同一次迭代中补齐能力缺口

2026-09-07，用户确认 Q7、Q8 推荐方案。Agent 先自行读取实现、发现能力及技术缺口，只向用户确认目标歧义、影响使用方式的行为取舍和范围变化。技术路径由 Agent 决定；需求明确且用户点击开始执行后，自主生成、验证和修正候选，最终请求应用确认，不把能自行查明的问题交给用户。

在明确的需求范围内，必要的接口、运行能力和业务实现纳入同一个变更，整体构建、验证并供用户确认。需要重启时明确展示；触及保护范围才转维护者升级。不要求用户另开技术任务补接口，也不能暗中降低目标。相较于只生成现有接口内的插件，这要求候选与验证覆盖完整变更，但避免将现有扩展契约固化为永久能力上限。

用户在 Q15 强调先做 Plan：在规划阶段调查执行可能涉及的细节，包括相关实现、依赖和能力缺口、验证及应用方式，尽量提前发现障碍，不能用浅层步骤列表代替调查。已知且会阻止执行的问题应在开始前澄清或明确呈现。执行中仍遇到必须改变需求范围或触及保护范围的障碍时，停止本次执行，保留诊断和候选；调整需求后重新规划和开始，旧候选不能直接应用。范围内的代码修正继续自动进行，不因普通测试失败要求重新确认。
