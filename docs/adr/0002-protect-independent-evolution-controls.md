# 自迭代不能修改自身的独立约束

2026-09-07，用户确认 Q4 推荐方案。工具授权、运行预算与取消机制、已确认的验收断言、验证结果记录、发布事务和恢复入口属于保护范围，普通自迭代不能自行修改。否则 Agent 可以通过削弱评价与控制条件，将失败伪装为成功。

业务代码、界面和扩展接口允许迭代。用户在 Q12 明确禁止 Agent 修改自己的执行策略，以保持自迭代核心能力稳定；此决定覆盖此前允许策略自修改的建议，执行策略纳入保护范围。策略的必要修改走维护者升级流程，不属于普通自迭代能力。

用户在 Q11 确认区分业务验收与系统保护约束。用户明确改变业务要求后，Agent 展示受影响的旧规则及替代规则，确认后建立新修订，并保留旧版本的验收记录；不能为使候选通过而自行删除或削弱断言。数据保留、授权、取消、发布一致性等系统保护约束不能由普通迭代修改。结合 Q10，这类需求及业务验收调整发生在执行前或后续迭代，不在活动执行中修改。

保护部分的必要修改走维护者升级流程。此约束不禁止本次经用户确认的工程重构修改相关实现，但不授予重构后的 Agent 修改这些保护项的权限。
