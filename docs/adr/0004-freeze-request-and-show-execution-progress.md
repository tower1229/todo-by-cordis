# 执行期间锁定需求并展示真实进度

2026-09-07，用户在 Q10 决定为简化行为、防止意外，Agent 执行期间不能改变需求，不采用执行中接收目标变更并重新规划的方案。Agent 执行前形成大致过程计划，并通过可视化进度页面让用户看到实际进展。锁定需求不取消已有停止执行的能力；停止后保留记录，调整需求须重新规划并开始。

用户在 Q13 确认固定流程：澄清需求与调查 → 展示目标、验收和大致步骤 → 用户点击开始执行并锁定需求 → 自动生成、验证和修正 → 体验候选 → 确认应用。执行中不逐步询问。Plan 必须先调查潜在障碍，见 ADR 0003。

用户在 Q14 确认保留侧栏作为需求沟通入口，开始执行后进入专门的进度视图。展示计划步骤、当前阶段、实际结果及修正尝试，详细日志折叠。用户可以离开继续使用 Todo，回来或刷新后恢复进度；执行期间隐藏需求编辑入口，保留停止操作。

进度依据服务端真实执行事件展示，不用定时器或模型自述伪造推进，不显示假百分比；阶段失败和修正尝试保留。候选验证完成后仍须独立的应用确认，不能把点击开始执行当作正式应用授权。
