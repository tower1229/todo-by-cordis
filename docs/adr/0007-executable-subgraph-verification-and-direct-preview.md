# 按插件依赖子图分层可执行验证与直达预览闭环

2026-11-19，针对 V2 形式化规格编译器与空历史双模型复核在连续自迭代中暴露的系统性阻塞，确立 V3 验证与交互闭环，并更新 [ADR 0004](0004-freeze-request-and-show-execution-progress.md) 的前置开始门禁。

## 背景与问题

V2 要求模型在编写代码前输出形式化需求规格、原文引文绑定与验收义务，由约 2.2 万行宿主编译代码推导全局 `BrowserCase` 并经空历史第二模型审查。实测表明模型编写插件代码仅需约 10 秒，但近 100% 的连续六步运行卡死在规划编译、案例配额膨胀、跨插件拦截踩踏与双模型语义分歧阶段（累计 679 次调用完整六步通过数为 0），且规格编译器与 Todo 语义深度绑定无法跨业务迁移。

## 决策

1. **退役形式化规格编译器与空历史双模型法庭**：不再将自然语言编译为宿主自定义的 `Obligation` / `BrowserCase` 中间语言，也不再串联空历史 LLM 做前置语义法庭。模型在沙箱中直接编写全栈 Cordis 插件源码与标准 TypeScript 可执行测试（服务/API 集成测试与 Playwright 浏览器测试）。
2. **双层可执行验证拓扑（子图隔离契约 + 全组合实证）**：
   - **最小依赖子图契约测试（`closure(P)`）**：每个插件 `P` 绑定自身契约测试，在仅挂载 `P` 及其 `inject` 依赖祖先的子图中执行，互不加载无关兄弟插件或下游拦截插件，根治多插件特性交互导致的测试连坐与停用插件时的案例裁剪难题；
   - **红绿差分约束**：新增或修改业务行为时，新测试默认须在旧版本子图/组合上失败（红）、在候选版本上通过（绿）；纯视觉调整或纯内部重构无行为差异时，不在代码层强造脆弱断言，而是在《变更简报》中显式标记“无行为差分断言，请人工核验预览”；
   - **真实克隆数据与轻量全组合端到端验证**：沙箱克隆正式 SQLite 真实数据，挂载全部 `enabled: true` 插件执行启动、历史数据无损保留校验及轻量全组合关键路径冒烟。若本轮需求主动修改了既有已启用插件的测试，宿主通过确定性 diff 在确认界面醒目列出修改项。
3. **明确需求直达预览与对话式微调**：仅当需求存在重大业务目标歧义或破坏性数据意图时前置澄清；需求明确时直接进入沙箱生成、验证并挂载隔离预览会话。用户可在预览界面直接对话对当前候选做增量微调，最终仍须经用户显式点击“应用确认”（[ADR 0001](0001-evolution-scope-and-application-confirmation.md)、[ADR 0002](0002-protect-independent-evolution-controls.md)）方可切换至正式环境。

## 后果

- 模型的反馈信号从“抽象 JSON 规格编译报错”变为其最擅长的“真实 TypeScript / Cordis 运行时 / Playwright 报错堆栈”，单轮闭环收敛速度提升一个数量级，且验证框架 100% 跨业务通用。
- 最终业务语义正确性由“红绿差分测试 + 真实克隆数据预览 + 既有测试 diff 透明披露 + 人工体验确认”共同保障，不再假定宿主能用静态规则证明自然语言完整性。
