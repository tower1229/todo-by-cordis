## 1. 依赖顺序与工作量

先完成 M0 技术验证，再进入 PRD 的 M1–M5。下面按一名熟悉 TypeScript/React 的全栈开发者、可使用 AI 辅助估计有效开发人日；是任务拆解估算，不是承诺，也没有包含任意模型都能成功生成的假设。

| 阶段 | 估计人日 | 前置 | 可评审产物与退出条件 |
| --- | --- | --- | --- |
| M0 关键验证 | 4–6 | 无 | 依赖锁、隔离报告、Cordis 生命周期测试、流程和发布恢复小原型 |
| M1 可用 Todo | 5–7 | M0 | 移动 CRUD、动作契约、持久化、认证、恢复页；无模型也可使用 |
| M2 插件 SDK | 6–9 | M1 | 能力目录、字段/UI/查询/服务代理、异步 jobs、依赖与清理；手写探针验证组合 |
| M3 改造发布 | 8–12 | M2 | 实际模型工具循环、候选库、独立门禁、手机预览/审批、发布与撤回 |
| M4 真生成场景 | 4–6 | M3 | 估时生成与迭代、组合筛选、review 流程、第二驱动替换证据 |
| M5 自修复与收口 | 7–10 | M4 | 故障归属/复现/修复、断点恢复、安全和实机验收、演示与自托管说明 |
| 合计 | 34–50 | 按依赖推进 | 加 20–30% 未知项缓冲约 41–65 人日 |

M0 后用实际结果重新估算。并行人员不能简单把工期除以人数，尤其是协议与发布事务的依赖。若只做 M1–M3 可得阶段原型，仍不能宣称完整 PRD 已完成。缩短工期优先减少视觉定制和非必需集成，不取消独立验证、真实生成或核心流程替换。

## 2. M0：先验证四个风险

| 验证 | 实验 | 通过判据 | 不通过时 |

## 5. CI 与验证策略

拟配置三个门禁：PR 基础类型/领域/契约测试；候选生成沙箱与受影响组合/移动测试；发布前绑定候选 hash 的完整保护回归。真实模型验收单独执行、独立标注，不拿固定桩冒充生成效果。任何“通过”需附环境与报告引用。

保护性测试、verifier 和 publisher 目录不进入 Agent 可写区域。测试必须断言业务正例和负例；例如短任务筛选既要排除 unknown，也要纳入 20，防止吞异常返回空值过关。

性能使用 PRD 的约定场景：1000 任务、10 扩展；记录设备、网络、浏览器、服务器、模型、样本数和 P95/P75。热切换测停写段。未测显示“未测”，不能复制 PRD 目标作为实测结果。

自动化浏览器覆盖 320/390/768/1280；Safari 与 Android Chrome 仍需真实设备核验，模拟器通过不替代 AC-35/36/37 的实机部分。

## 6. 自托管与运行交付

目标部署为一台 Linux 主机，反向代理提供 HTTPS，API/DB/产物持久卷，受保护 runner-manager 按需启动隔离容器。模型调用经 broker。Windows/macOS 开发通过可提供等效限制的 Linux 容器环境，差异在 M0 报告。

首次启动默认本机绑定，初始化所有者认证；开放手机入口前配置 TLS 与会话认证。无模型时 Todo 正常，模型不可用时 AI 入口明确禁用。Cookie HttpOnly/SameSite，远程 HTTPS 下 Secure；生产请求校验 Origin/CSRF。不在 URL 放访问密钥。

交付时提供固定版本的安装/启动/升级/备份/恢复命令、环境变量说明（仅示例占位值）、持久卷位置、模型连接测试、日志脱敏、配额、故障排查。此处不提供尚不存在的 `pnpm dev` 等可运行承诺；M1 创建脚本后同步 README。

应用健康区分 liveness、基础数据 readiness、插件状态和模型可用性。模型断开不能把 Todo 标成整体不可用。部署不具备 runner 隔离时必须显示生成禁用原因。

## 7. 连续演示与证据

1. 空用户插件区，手机创建/修改/完成任务，展示基础应用已运行。
2. 对话更改主题，查看配置版本并撤回一次。
3. 现场生成估时，查看新源码 hash、权限与验证，手机批准后创建任务触发真实模型。
4. 继续修改同插件，让人工值优先，验证身份与数据保留。
5. 现场生成 20 分钟筛选，展示消费既有接口；检查缺值/边界输入。
6. 替换 review 工作流，已有 open/done 保留；表单取消不完成；验证有 review 任务时的撤回。
7. 明示加载缺陷筛选版，触发最小样例；现场生成修复，展示 old fail/new pass 与不变的保护基线。
8. 刷新与重启，核对插件/字段/组合；展示依赖停用和恢复入口。

最终报告分为实测通过、失败、未执行；列出真实模型调用与桩测试数量。演示失败保留证据和当前可用组合。M4 场景可以固定需求提示，但不能把 M2 手写探针直接拿来伪装现场生成。
